## 4. Живая демонстрация сайта (5–7 минут)

1. Главная → каталог.
2. Фильтр «Люкс» → «Применить»: остаются только люксы. «Сбросить фильтр» возвращает подборку.
3. Открыть номер → показать календарь: занятые дни неактивны, прошедшие дни неактивны.
4. Отправить пустую форму → ошибки у каждого поля.
5. Ввести телефон без формата, кривой e-mail и вчерашнюю дату → три ошибки.
6. Заполнить корректно → экран «Заявка отправлена».
7. Войти в админку: `hotel123` / `change-me` → в списке новая заявка.
8. Одобрить заявку → вернуться в календарь: даты стали занятыми.
9. Попробовать забронировать те же даты → сервер отклоняет пересечение.
10. Открыть phpMyAdmin → показать запись в `bookings` со статусом `approved`.
11. Вернуться в терминал → `git log --oneline`.

## 5. Порядок файлов в папке сдачи

Показывать сверху вниз, не открывая всё подряд:

```text
4/
├── README.md                  # что реализовано и как запустить
├── docs/
│   ├── demo-order.md          # этот файл
│   ├── uml-use-case.svg       # диаграмма прецедентов
│   ├── uml-class.svg          # диаграмма классов
│   ├── exam-guide.md          # разбор всех четырёх заданий
│   ├── test-report.md         # отчёт о проверке
│   └── sources.md             # источники
├── prototypes/
│   ├── index.html             # прототип главной
│   ├── catalog.html           # прототип каталога
│   └── booking.html           # прототип бронирования
├── db/
│   ├── schema.sql             # структура БД
│   └── seed.sql               # демо-данные
├── app/
│   ├── actions.php            # контроллеры
│   ├── validation.php         # серверная валидация
│   ├── repository.php         # запросы и транзакции
│   └── views/                 # шаблоны страниц
└── public/
    ├── index.php              # фронт-контроллер
    └── assets/                # CSS, JS, изображения
```

## 6. Что говорить по критериям

| Критерий КИМ | На что ссылаться |
|---|---|
| Проектирование информационных ресурсов | `docs/uml-use-case.svg`, `docs/uml-class.svg`, `db/schema.sql`, карта маршрутов в `public/index.php` |
| Интеграция программного кода в инфраструктуру | `public/index.php`, `app/bootstrap.php`, `app/config.php`, `.htaccess`, импорт `db/schema.sql` и `db/seed.sql` |
| Разработка интерфейсов пользователя | `prototypes/*.html`, `app/views/*.php`, календарь в `booking.php`, адаптивная вёрстка |
| Система контроля версий | `git log --oneline`, `.gitignore`, ссылка на удалённый репозиторий |
| Поиск и интерпретация информации | `docs/sources.md`: PDO, `FOR UPDATE`, MDN, PlantUML |
| Создание серверного кода по ТЗ | `app/actions.php`, `app/validation.php`, `app/repository.php` |
| Отладка серверного кода | `docs/test-report.md`, обработка 404/419, сообщения об ошибках |

## 7. Риски, которые лучше закрыть до защиты

1. **Шаблон `Прил_1` не использован.** Это самое слабое место проекта: в КИМ
   сказано, что сервис реализуется на выданном шаблоне. Если шаблон появится —
   перенести в него `app/views/*.php`, сохранив классы и структуру. Если нет —
   быть готовым объяснить, что логика отделена от вёрстки и переносится.
2. **Git только локальный.** Нужно создать удалённый репозиторий и показать
   ссылку; иначе критерий «система контроля версий» закрыт не полностью.
3. **Перед показом проверить окружение:** PHP 8+, MySQL, импортированы
   `db/schema.sql` и `db/seed.sql`, сайт открывается через `public/`.
4. **Не путать прототипы с рабочим сайтом.** `prototypes/` — статические
   страницы Задания 2; рабочая версия — `public/index.php`.
5. **Пароль администратора** `hotel123` / `change-me` — требование КИМ; в БД
   хранится bcrypt-хеш, исходный пароль используется только при первом входе.
6. **Дата выезда не блокируется в календаре** — это осознанное правило:
   выезд считается днём освобождения номера. Объяснение есть в `README.md`,
   раздел 4.
