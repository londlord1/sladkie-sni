# «Сладкие сны» — сервис бронирования номеров

Эталонный проект к демонстрационному экзамену по специальности **09.02.09 «Веб-разработка»**, квалификация **«Разработчик веб-приложений (разработка веб-приложений на стороне сервера)»**, КИМ 09.02.09-2-2027, инвариантная часть (ДЭ БУ / ПА).

> **Папка 4 репозитория SPA.** Пошаговый разбор всех четырёх заданий — в [`docs/exam-guide.md`](docs/exam-guide.md). При развёртывании папку `4` можно переименовать в `hotel-sweet-dreams` — на код это не влияет.

Стек: **PHP 8 + MySQL (PDO) + HTML/CSS/JS без фреймворков**. Такой набор соответствует оснащению ЦПДЭ (Apache/XAMPP, MySQL, PHP) и не требует установки пакетов из интернета.

## 3. Установка (XAMPP)

1. Скопируйте папку `hotel-sweet-dreams` в `C:\xampp\htdocs\`.
2. Запустите **Apache** и **MySQL** в панели XAMPP.
3. Откройте `http://localhost/phpmyadmin`.
4. Вкладка **Импорт** → файл `db/schema.sql` → **Вперёд**.
5. Снова **Импорт** → файл `db/seed.sql` → **Вперёд**.
6. При необходимости поправьте `app/config.php`:
   ```php
   'db' => [
       'dsn' => 'mysql:host=127.0.0.1;dbname=hotel_sweet_dreams;charset=utf8mb4',
       'user' => 'root',
       'password' => '',
   ],
   ```
7. Откройте сайт: `http://localhost/hotel-sweet-dreams/public/`.
8. Админка: `http://localhost/hotel-sweet-dreams/public/index.php?r=admin.login`.

**Логин:** `hotel123`  
**Пароль:** `change-me`

Учётная запись создаётся автоматически при первом открытии страницы входа: пароль хешируется `password_hash()` и сохраняется в таблицу `admins`. В БД пароль в открытом виде не хранится.

### Вариант без Apache

Из папки проекта:

```bash
php -S localhost:8000 -t public
```

Сайт: `http://localhost:8000/`. Нужны PHP 8.0+ с расширениями `pdo_mysql` и `mbstring`, запущенный MySQL.

> В реальном экзамене вёрстка выдаётся в архиве `Прил_1_ОЗ_КИМ_...zip`. Правильный порядок — перенести PHP-логику в выданный шаблон, сохранив его классы и структуру, а не заменять макет своим. Этот проект можно использовать как рабочий референс.

## 4. Модель данных

```
categories 1 ── * rooms 1 ── * bookings
                     *
                     *
                room_amenities * ── 1 amenities

admins — отдельная таблица для панели управления
```

Ключевые ограничения:

- `bookings.check_out > bookings.check_in` — CHECK-ограничение;
- `rooms.price >= 0`, `capacity > 0` гарантируются валидацией и типом;
- индекс `(room_id, status, check_in, check_out)` ускоряет проверку пересечений;
- внешние ключи запрещают заявку на несуществующий номер.

### Семантика дат

Дата выезда — **день освобождения номера**. Бронь `10.01–13.01` занимает ночи 10, 11, 12 января; с 13.01 номер можно бронировать снова. Поэтому пересечение проверяется формулой:

```sql
existing.check_in < new.check_out AND existing.check_out > new.check_in
```

В календаре занятыми показываются дни `[check_in; check_out)`, то есть день выезда остаётся свободным. Если преподаватель требует блокировать и день выезда, замените условие в `calendar_cells()` на `<=` и в `is_room_free()` на `<=` — но это уже другая бизнес-логика, проговорите её на защите.

## 6. Серверная валидация (ключевой фрагмент)

`app/validation.php`:

```php
if (!preg_match('/^[А-Яа-яЁё][А-Яа-яЁё\s.\-]*$/u', $data['first_name'])) {
    $errors['first_name'] = 'Имя может содержать только буквы кириллицы, пробел, точку и дефис.';
}

if (!preg_match('/^\+7\(\d{3}\)\d{3}-\d{2}-\d{2}$/', $data['phone'])) {
    $errors['phone'] = 'Телефон должен быть в формате +7(ХХХ)ХХХ-ХХ-ХХ.';
}

$today = new DateTimeImmutable('today');
$checkIn = DateTimeImmutable::createFromFormat('!d.m.Y', $data['check_in']);
if (!$checkIn || $checkIn->format('d.m.Y') !== $data['check_in']) {
    $errors['check_in'] = 'Дата заезда должна быть в формате ДД.ММ.ГГГГ.';
} elseif ($checkIn < $today) {
    $errors['check_in'] = 'Дата заезда не может быть раньше сегодняшней.';
}
if ($checkOut !== null && $checkIn !== null && $checkOut <= $checkIn) {
    $errors['check_out'] = 'Дата выезда должна быть позже даты заезда.';
}
```

Правила:

| Поле | Правило |
|---|---|
| Имя, фамилия | Обязательно, до 64 символов, кириллица, пробел, точка, дефис |
| Телефон | Обязательно, строго `+7(XXX)XXX-XX-XX` |
| E-mail | Обязательно, `FILTER_VALIDATE_EMAIL`, до 190 символов |
| Заезд | Обязательно, `ДД.ММ.ГГГГ`, не раньше сегодня |
| Выезд | Обязательно, `ДД.ММ.ГГГГ`, строго позже заезда |
| Номер | Существует и активен |
| Период | Не пересекается с одобренными бронями |

## 7. Проверка пересечений и гонки

`app/repository.php`, функция `create_booking()`:

```php
$pdo->beginTransaction();
$stmt = $pdo->prepare('SELECT id FROM rooms WHERE id = ? AND is_active = 1 FOR UPDATE');
$stmt->execute([$data['room_id']]);

if (!is_room_free($data['room_id'], $data['check_in_iso'], $data['check_out_iso'])) {
    throw new DomainException('На выбранные даты номер уже забронирован.');
}

$stmt = $pdo->prepare(
    'INSERT INTO bookings (room_id, first_name, last_name, phone, email, check_in, check_out, status)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?)'
);
$stmt->execute([...]);
$pdo->commit();
```

`SELECT ... FOR UPDATE` блокирует строку номера, пока транзакция не завершится. Два одновременных запроса на один номер не смогут оба пройти проверку и вставить пересекающиеся брони. Это ответ на вопрос «зачем транзакция, если проверка уже есть».

При одобрении заявки проверка повторяется (`set_booking_status()`), потому что между созданием заявки и её одобрением могла появиться другая подтверждённая бронь.

## 8. Задание 4: календарь и админ-панель

### Календарь

- Строится на сервере в `calendar_cells()`: первый день месяца, смещение понедельника, количество дней.
- Диапазоны одобренных броней приходят из `approved_intervals()`.
- День блокируется, если `check_in <= day < check_out`.
- Прошедшие дни некликабельны, сегодняшний выделен рамкой.
- Клик по свободному дню подставляет дату заезда, второй клик — дату выезда.
- JS (`public/assets/js/booking.js`) проверяет формат, порядок дат и пересечение с занятыми периодами, но **окончательное решение принимает сервер**: даже прямой POST с занятыми датами вернёт ошибку.

### Админ-панель

- Вход по логину `hotel123` и паролю `change-me`.
- Пароль хранится как bcrypt-хеш, проверка — `password_verify()`.
- После входа — `session_regenerate_id(true)`.
- 5 неудачных попыток в рамках сессии блокируют вход на 60 секунд.
- Список заявок фильтруется по статусу, показывает контакты, номер, даты и дату создания.
- Доступные действия: одобрить, отклонить, удалить (с подтверждением).
- Одобрить пересекающуюся заявку нельзя — выводится информативное сообщение.

## 9. Безопасность: что и где

| Угроза | Защита | Файл |
|---|---|---|
| SQL-инъекции | Prepared statements, whitelist статусов, `(int)` для LIMIT | `repository.php` |
| XSS | `e()` = `htmlspecialchars(ENT_QUOTES)` на выводе | `helpers.php`, все views |
| CSRF | Токен в сессии + скрытое поле + `hash_equals()` | `helpers.php`, формы |
| Подделка сессии | `HttpOnly`, `SameSite=Lax`, `session_regenerate_id` | `bootstrap.php`, `repository.php` |
| Подбор пароля | bcrypt + ограничение попыток | `repository.php`, `actions.php` |
| Доступ к исходникам | `app/` и `db/` вне `public/`, `.htaccess` с `Require all denied` | `.htaccess` |
| Некорректные даты | `createFromFormat` + обратная проверка формата | `validation.php` |
| Двойная бронь | Транзакция + `FOR UPDATE` + повторная проверка | `repository.php` |

Пароли и логин администратора в демо заданы в `config.php`, потому что это требование экзамена. В реальном проекте их хранят в переменных окружения.

## 14. Возможные вопросы эксперта

**Почему валидация на сервере, если есть JS?**  
JS можно отключить или обойти через прямой POST. JS нужен только для удобства; сервер проверяет всё заново.

**Почему не используется фреймворк?**  
В ЦПДЭ не гарантирован Composer и интернет. Чистый PHP 8 + PDO покрывает требования КИМ и не создаёт зависимостей.

**Как защищены SQL-запросы?**  
Все пользовательские значения передаются в подготовленные выражения. Динамически собираются только фрагменты с `?`, сортировка и LIMIT задаются кодом, а не пользователем.

**Что будет при одновременной отправке двух заявок?**  
`SELECT ... FOR UPDATE` в транзакции сериализует доступ к номеру; вторая транзакция увидит первую бронь и получит отказ.

**Где хранится пароль администратора?**  
В `admins.password_hash` в виде bcrypt-хеша. Исходный пароль из `config.php` используется один раз при создании учётной записи.

**Почему дата выезда не блокируется в календаре?**  
Выезд — утро дня освобождения. Номер можно заселить снова в этот же день. Это сознательное бизнес-правило, оно описано в разделе 4.

**Как реализована случайная выборка?**  
`ORDER BY RAND() LIMIT 6`. Для маленького каталога это нормально; для больших таблиц используют выборку по случайному ключу.

## 15. Если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| «Не удалось подключиться к базе» | MySQL не запущен / неверные данные | Запустить MySQL, проверить `app/config.php` |
| Пустая страница, 500 | Ошибка PHP | Включить `debug => true`, посмотреть `C:\xampp\apache\logs\error.log` |
| Нет стилей | Открыт URL без `/public/` | Открыть `.../public/index.php` |
| Не входит админ | Пароль изменён после создания | `DELETE FROM admins;` и открыть страницу входа заново |
| CSRF-ошибка | Истекла сессия | Обновить страницу, отправить форму заново |
| Даты «съехали» | Часовой пояс | Указать регион в `config.php` |
